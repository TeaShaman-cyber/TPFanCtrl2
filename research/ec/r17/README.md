# R17 persistent dispatcher slice

Ghidra 12.2 / JDK 25. Extract the original firmware locally from the official Lenovo package; no firmware bytes are included. Run with the pinned payload SHA, headless launcher and output log as arguments to run.sh.

ROM is mapped at 0x20100, so the original indirect dispatcher at raw offset 0x190da can follow its unmodified tables. Task 24 maps to record 0x11454. The test seeds stage 11, substep 8, processed feedback FFFF and prior miss count 7 or 8. It exercises eighth/ninth-invalid cases, then calls only the original dispatcher until stage 7; RAM persists between calls. Virtual time is advanced by the harness. The ROM timer calls are explicitly modeled, notification is a stub, and timer units are not established as milliseconds. PWM and other selected MMIO ranges use synthetic memory latches; real interrupt delivery and tachometer hardware are not modeled. Unknown LOAD/STORE ranges and unknown executable addresses stop execution; this is not a proof of coverage of all memory accesses. The test explicitly checks rejection of an out-of-range read using the guard itself. SP, return address, argument and PSR are reseeded at each dispatcher invocation. This is not a bootable whole-board emulator, physical fan model, or a reproduction of sleep/resume. The initial processed tach sample and initial state are fixtures, not obtained from a simulated sensor.

Expected: eighth invalid stays stage 11; ninth enters stage 12, raises floor 25 to 401 from output 400, disables PWM, waits until virtual time 500, restarts output 500, preserves floor, enters stage 7. Compare existing conditional instruction probes in local-lab#289. Do not use this harness to write real EC registers.

## Signal-loss scenario (run.sh fourth argument: signal)

The signal scenario starts at stage 11/substep 3 with synthetic channel and normal-mode configuration. Original capture handler f0fe is called for two synthetic capture-A events (period 12000 counts); beforeLoad supplies the captured counter and event flag, beforeStore models clearing the event. The unmodified dispatcher arms acquisition, waits, converts the capture to 5000 RPM, filters, validates and selects the next stage. Withhold both events for nine acquisition windows. No processed error value, miss counter, stage or substep is injected after initialization. The harness advances virtual time by the modeled deadlines (100/250 ticks); on the ninth failed measurement the original firmware selects recovery. The same machine executes recovery through disabling PWM and restarting at maximum; lower limit rises from 25 to 381 after normal correction to output 380. A control with eight failed windows, a valid signal and a subsequent failed window verifies reset of the consecutive-miss count (0 then 1) and no recovery. This is a software counterexample for the seeded normal-regulation state, not a proof that this state is reached in BIOS mode on the real L14. No physical motor dynamics, real interrupt delivery, OS EC port transactions, or resume event are modeled. The 500-tick delay is not established as 500 milliseconds. Actual acoustic noise is not simulated.

## Return after signal loss (run.sh fourth argument: return)

Extends the signal fixture with a ROM target-table pointer (0x5876e), restart threshold 2000 and ramp interval 250. These are fixture values, not a full boot or proven live configuration. After the nine missing windows and restart, original dispatcher executes stages 7, 8, 9, 10 and 11. Five synthetic capture events in each restart/ramp acquisition window supply 12000-count periods; the first restart event is discarded by the firmware's driver state. Residual status clear of the outer interrupt wrapper is modeled by the harness, not executed. The deadline service at mapped 0x16aaa returns signed modular remaining time; virtual time advances to deadlines, with no wall-clock claim. Target 3950, measured 5000, misses zero, floor and output 381 after return; six further normal acquisition/filter/validation cycles preserve floor/output 381. No-fault control with the same signal reaches output 280, floor 25. These are controller responses to fixed synthetic feedback, not predictions of physical RPM or acoustics. No writes to stage, miss counter, processed feedback or floor after initialization. Real BIOS policy reachability, electrical cause of signal loss and safe host-accessible reset remain unknown.

## Command and stop/restart recovery (run.sh fourth argument: commands)

Extends the complete signal-loss/return scenario without resetting its RAM state. Calls original fan command callback with 0–7, 0x40 and 0x80 (not the entire host transport), then issues zero and follows original dispatcher stages 13/4/5 until output=0 and PWM enable is clear. Advances virtual clock to modeled deadlines. Issues level 5 and follows stages 5/6/7 to output=500. Floor remains 381 throughout. No claim of safe live fan-off testing or complete host command coverage; only virtual experiments. Full platform reset/lifecycle paths remain to be traced.
